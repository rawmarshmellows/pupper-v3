# EEPROM (Electrically Erasable Programmable Read-Only Memory)

**[[learning/notes/quick-context/capacitance|Definition]]:** [[learning/notes/quick-context/anions-and-oxidation|A]] [[learning/notes/quick-context/tensile-strength-materials|]]non-volatile [[learning/notes/quick-context/bare-minimal-data-storage-circuit|memory]] chip that retains data without [[learning/notes/quick-context/d-flip-flop|power]], [[learning/notes/quick-context/embedded-communication-protocols|can]] be electrically rewritten [[learning/notes/quick-context/how-source-code-is-stored|byte]]-by-byte, [[learning/notes/micro-context/push-pull-vs-open-drain|and]] is used to store small amounts of configuration data (typically [[learning/notes/quick-context/meddpicc-qualification-framework|1]] KB – 64 KB). It sits between [[learning/notes/quick-context/ram-addressing-decoder|one]]-time-programmable ROM ([[learning/notes/quick-context/d-flip-flop|write]] once) and [[learning/notes/micro-context/sram|SRAM]] (volatile, loses data on power-[[learning/notes/quick-context/bjt-specifications|off]]).

## How It Works

- Each bit is stored as [[learning/notes/quick-context/cations-and-reduction|charge]] trapped on a **[[learning/notes/quick-context/physics-of-writing-data-to-memory|floating gate]]** — a conductive [[learning/notes/quick-context/pcb-assembly-files-bom-cpl|layer]] surrounded by insulating oxide, sitting between a [[learning/notes/micro-context/mosfet|MOSFET's]] control [[learning/notes/quick-context/transistor|gate]] and [[learning/notes/micro-context/mosfet|channel]].
- **Write:** A high [[learning/notes/quick-context/voltage|voltage]] (~10-20V, generated by an on-chip charge pump) forces [[learning/notes/quick-context/anions-and-oxidation|electrons]] through [[learning/notes/quick-context/capacitance|the]] oxide [[learning/notes/quick-context/metal-interconnect-layers|via]] [[learning/notes/quick-context/physics-of-writing-data-to-memory|Fowler-Nordheim tunneling]], trapping them on the floating gate. This shifts the [[learning/notes/quick-context/silicon-die|transistor]]'s [[learning/notes/micro-context/capacitive-voltage-sensing|threshold]] voltage, changing the stored bit.
- **Erase:** A reverse voltage pulls electrons back off the floating gate, resetting the bit.
- **Read:** A normal read voltage is applied to the control gate. If the floating gate [[learning/notes/quick-context/pupper-lab7-vision-tracking|holds]] charge, the transistor's threshold is shifted and it doesn't conduct → reads as [[learning/notes/quick-context/meddpicc-qualification-framework|0]]. [[learning/notes/micro-context/capacitive-voltage-sensing|No]] charge → conducts → reads as 1.

```
EEPROM CELL (floating-gate MOSFET)
════════════════════════════════════════

     Control Gate ──────────────┐
                          ┌─────┴─────┐
      Oxide insulator ──► │///////////│
                          ├───────────┤
      Floating Gate ────► │  trapped  │ ← electrons stored here
                          │  charge   │
      Oxide insulator ──► │///////////│
                          ├───────────┤
      Channel ──────────► │  Si body  │
                          └─────┬─────┘
                          Source   Drain

  Write: high voltage tunnels e⁻ onto floating gate
  Erase: reverse voltage pulls e⁻ off
  Read:  charge present → threshold shifted → bit = 0
```

**Key insight:** EEPROM is slow to write (~5-10 ms per byte) and has limited write cycles (~100K–1M), but it's perfect for storing small config data that rarely changes — device IDs, calibration values, [[learning/notes/micro-context/push-pull-vs-open-drain|or]] HAT identification. Flash memory uses the same floating-gate principle but erases in large blocks rather than individual [[learning/notes/quick-context/how-source-code-is-stored|bytes]], trading granularity for [[learning/notes/quick-context/bond-pad|density]] and [[learning/notes/quick-context/embedded-communication-protocols|speed]].

## Common Uses

- **Raspberry Pi HAT EEPROM:** Stores a device tree overlay telling the Pi [[learning/notes/quick-context/bare-minimal-data-storage-circuit|what]] the board is and how to configure itself at boot (read via [[learning/notes/micro-context/i2c|I2C]] on [[learning/notes/quick-context/raspberry-pi-5-components|GPIO]] 0 & 1)
- **[[learning/notes/micro-context/microcontroller|Microcontroller]] calibration:** Factory-programmed temperature sensor offsets, oscillator trim values
- **[[learning/notes/quick-context/data-bus-and-arbitration|Serial]] number / MAC [[learning/notes/quick-context/how-source-code-is-stored|address]] [[learning/notes/quick-context/3d-printing-filament-refill-vs-spool|storage]]** on network devices
