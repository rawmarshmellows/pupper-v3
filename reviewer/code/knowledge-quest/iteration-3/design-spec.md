# Knowledge Quest -- Iteration 3 Design Specification

## Changes from Iteration 2

### Priority Fix 1: Intrinsic Integration (partial -> targeting deep)

**Problem:** Hardcoded diagnosis symptoms and prediction scenarios were disconnected from topics. Terms and quiz questions leaked across domains (sales terms in electronics regions). Negotiate and Teach Apprentice were "type your answer" quizzes with narrative dressing.

**Changes:**

1. **Topic-specific symptoms in Diagnosis encounters.** Replaced 5 hardcoded generic symptoms with `generateTopicSymptom(topic)` that derives failure modes from the topic's key_insight/definition content. A capacitor topic now presents ripple/filtering symptoms; a resistor topic presents current/voltage drop symptoms; a PID topic presents overshoot/oscillation symptoms. The symptom relates to what the component actually does.

2. **Topic-derived scenarios in Predict Behavior.** Replaced 5 hardcoded scenarios with `generateTopicScenario(topic)` that constructs thought experiments specific to the topic. A capacitor topic asks about halving capacitance and cutoff frequency. An inductor topic asks about opening a switch. These scenarios require understanding the specific component, not generic circuit knowledge.

3. **Category-based region filtering.** Added a `category` column to `context_documents` and a `classify_category()` function in the importer that maps each document to one of: electronics, semiconductors, manufacturing, protocols, embedded, robotics, chemistry, sales, other. Each region specifies its categories. The `/api/terms/random` and `/api/quiz/random` endpoints accept `?categories=` parameter. The game passes region categories when fetching encounter content, preventing sales questions from appearing in the electronics workshop.

4. **Redesigned Negotiate encounter.** Removed the CHA bluff escape hatch entirely. Replaced the single "define this term" prompt with three knowledge-requiring approaches: (a) explain the term, (b) describe a practical use case, (c) ask a clarifying question then explain. All three require domain reasoning. The stat system never bypasses knowledge challenges.

5. **Redesigned Teach Apprentice encounter.** Instead of "explain the answer to this question" (identical to other encounters), the apprentice now presents a wrong answer generated by `generateWrongAttempt()`. The player must identify what's wrong and correct the reasoning. This requires evaluative thinking (Bloom's level 5) -- understanding not just the right answer but why a plausible-sounding wrong answer is wrong.

### Priority Fix 2: Pedagogical Soundness (mixed -> targeting strong)

**Changes:**

1. **Lowered semantic similarity thresholds.** Server `/api/evaluate` now uses: correct >= 0.75 (was 0.85), partial >= 0.55 (was 0.70). This accepts valid paraphrases that demonstrate understanding in different words rather than requiring near-exact reproduction.

2. **Wiki-link markdown stripped during import.** Added `strip_wiki_links()` function called on all extracted quiz questions, terms, definitions, TLDRs, and key insights. No `[[target|display]]` syntax reaches the player.

3. **CHA bluff escape hatch removed.** The Negotiate encounter no longer offers a CHA check to bypass defining a term. All encounter types require knowledge to succeed.

4. **Distractors from document_links.** New `/api/distractors/:id` endpoint returns linked documents first (related-but-different concepts from the knowledge graph), falling back to semantically similar documents. Circuit Build and Component Choice encounters use this endpoint instead of generic `/api/similar`. This produces pedagogically stronger distractors because wiki-links represent intentional conceptual relationships.

5. **Removed Bloom's Level display** from Apply Knowledge encounters that broke the stealth assessment frame.

### Priority Fix 3: Motivation (mixed -> targeting intrinsic)

**Changes:**

1. **"Unlock by understanding" gates.** Region unlocking is now based on mastery of the previous region (40% of topics mastered), not player level/XP. You advance by demonstrating understanding, not by grinding encounters.

2. **Mastery-centric HUD.** Replaced the XP bar and gold counter with a mastery bar and mastered topic count. XP/gold rewards are de-emphasized (smaller, dimmer text) while mastery progress messages are prominent (purple "Mastery: topic -- understanding deepens" messages).

3. **Mystery solutions require domain knowledge.** Each region has a `mysteryAnswer` with a specific technical explanation. When enough clues are gathered, the mystery becomes "solvable" but does NOT auto-solve. The player must explain the root cause and fix in their own words, evaluated against the mystery answer via semantic similarity. The mystery reward is the satisfaction of synthesis, not just XP/gold.

4. **Cross-topic challenges.** When a player has clues in 2+ regions, they can attempt a "Cross-Domain Challenge" from the world map. These present problems that span two regions (e.g., converting sensor data from the Control Sanctum into control signals for the Motion Arena). Success requires referencing concepts from both domains.

5. **Bloom's level tracking per topic.** `trackMastery()` now records the highest Bloom's level achieved for each topic. The character sheet shows Bloom's depth distribution (Remember: 5, Understand: 12, Apply: 8, Analyze: 3, etc.), giving players intrinsic feedback on the quality of their understanding, not just the quantity.

6. **Mastery progress shown on region cards.** Each region card on the world map shows a mastery meter (purple progress bar), making understanding visible and motivating completionism around knowledge rather than XP.

## Architecture

### Database Schema

Same as iteration 2, plus:
- `category TEXT NOT NULL DEFAULT 'other'` column on `context_documents`
- `CREATE INDEX ON context_documents (category)` for fast category filtering

### New/Modified API Endpoints

- `GET /api/terms/random?categories=electronics,semiconductors` -- category-filtered random term
- `GET /api/quiz/random?categories=robotics&level=3` -- category-filtered random quiz
- `GET /api/distractors/:id?count=3` -- linked docs as distractors, fallback to similar
- `GET /api/topics/random?category=electronics` -- category-filtered random topic
- `GET /api/search?q=term&category=electronics` -- category-filtered hybrid search
- `POST /api/evaluate` -- thresholds lowered to 0.75/0.55

### Category Classification

The importer classifies documents using keyword rules:
- **electronics**: resistor, capacitor, inductor, diode, voltage, current, power, etc.
- **semiconductors**: transistor, mosfet, bjt, op-amp, silicon, fabrication, etc.
- **manufacturing**: pcb, soldering, 3d-print, cnc, slicer, filament, etc.
- **protocols**: i2c, spi, can-bus, pwm, uart, swd, clock, etc.
- **embedded**: stm32, adc, imu, microcontroller, rtos, plc, mems, etc.
- **robotics**: pid, kinematic, gait, reinforcement, pupper, camera, etc.
- **chemistry**: atom, polymer, chemical-bond, covalent, oxidation, etc.
- **sales**: challenger, sandler, meddpicc, miller-heiman, etc.

Distribution: electronics 53, quick 123, chemistry 21, manufacturing 19, semiconductors 18, protocols 17, embedded 16, robotics 15, sales 10, other 15.

## Learning Objectives (Bloom's-Mapped)

| Objective | Bloom's Level | Game Mechanic |
|---|---|---|
| Recall component names from definitions | Remember (1) | Decode encounter |
| Explain what a component does | Understand (2) | Negotiate encounter, Library review |
| Select the correct component for a requirement | Apply (3) | Circuit Build, Component Choice |
| Diagnose failure modes from symptoms | Analyze (4) | Diagnosis encounter |
| Correct a wrong explanation | Evaluate (5) | Teach Apprentice encounter |
| Synthesize cross-domain solutions | Create (6) | Mystery solve, Cross-topic challenge |

## Freemium Design

- **Free tier**: All 6 regions, all 8 encounter types, mystery system, library, spaced repetition, full knowledge base, cross-topic challenges
- **Premium tier** (config only, not implemented): Advanced classes, bonus regions, cosmetics, challenge modes
- No paywalls, no energy gates, no dark patterns
